# 相談パケットを作る

種類：$ARGUMENTS（plan / design / stuck / risk）

空なら、状況から種類を1つ選び、ユーザーに「◯◯で作ります」と伝えてから進める。

Opus は高いので、**このパケットだけを読んで判断できる**ようにする。Opus はほかのファイルを読まない。

## 手順

1. 作業フォルダ（`.rails/` の該当フォルダ。分からなければ一番新しいもの）の requirements.md と、あれば plan.md を読む。
2. 種類に合わせて材料を集める。
   - **plan**：決まったタスク（ユーザーの言葉のまま全部）、受け入れ条件、関係するコード（変更しそうな関数・型の定義、呼び出し元）、既存テストのお手本を1つ、テストの実行方法
   - **design**：選択肢を2〜3個。それぞれ「どう作るか・長所・短所・影響する場所」
   - **stuck**：やりたいこと、試したこと（順番に）、エラーの全文（最後の50行まで）、関係するコード
   - **risk**：危ないファイルの差分だけ（`git diff <ベース>...HEAD -- <ファイル>`）、計画、受け入れ条件
3. コードは必要な部分だけ抜き出し、`ファイル名:行` を添える。**合計300行まで**。超えるなら、関係の薄いものから削る。
4. 「聞きたいこと」を**3つまで**に絞る。選択肢か、はい/いいえで答えられる形にする。
5. 作業フォルダに `consult-<種類>-<2桁の連番>.md` で保存する（形は下）。
6. ユーザーにこう伝えて終わる：「パケットを作りました（約◯行）。Opus に聞くなら `/opus-review <パケットのパス>` を打ってください。」
   - **自分では /opus-review を呼ばない。**

## パケットの形

```markdown
# 相談（<種類>）：<一行で>

## 何をしたいか（要件・受け入れ条件）

## 制約（守る決まり・使えないもの・期限）

## 今の案
<plan：タスクの一覧 / design：選択肢 / stuck：試したこと / risk：差分の説明>

## 関係するコード
### <ファイル名:行〜行>
（抜き出し）

## テストの書き方とお手本（plan のときだけ）
- 実行方法：
- お手本：<ファイル名>（抜き出し）

## 聞きたいこと
1. 
```

## 守ること

- パケットに、パスワード・トークン・個人情報・本番のデータを入れない。
- 材料が足りないと分かったら、推測で埋めずに「不明：〜」と書く。
