# テストを書く（実装の前）

## 手順

1. 作業フォルダの plan.md の「テストケース表」「テストの実行方法」と、各タスクの「お手本」を読む。
2. お手本になる既存のテストファイルを読み、**同じ書き方**にする（置き場所・ファイル名・書式・共通の部品）。
3. 表の1行＝テスト1つで書く。
   - テスト名に表の No を入れる（例：`No3 境界：小計10000円ちょうどは5%`）。
   - 期待値は表のとおりに書く。自分で計算し直したり、変えたりしない。
   - 表に無いテストは足さない。
   - 表に「仮定：」とあるものは、テスト名かコメントに「仮定」と書く。
4. テストを実行する。まだ実装していないので、**全部失敗するはず**。
   - 失敗の理由が「関数が無い」「期待と違う値」なら正しい。
   - **最初から通るテストがあれば**、何も確かめていない疑いがある。どの No かを報告し、直すかどうかユーザーに聞く。
   - 構文や import の誤りで動かないときは、テストの書き方を直してよい。
5. plan.md の「実装メモ」に「テスト作成：◯件、全件失敗を確認（YYYY-MM-DD HH:MM）」と書く。
6. 最初から通るテストがなければ（あればユーザーが決めてから）、テストのファイルだけをコミットする。メッセージは「テスト：<要件の一行>（実装前）」。
7. ユーザーに結果を伝え、「テストはここで固定します。次は `/clear` してから `/impl`」とすすめる。
   - `/impl` を使うと、そのセッションではテストのファイルを書き換えられなくなる（フックで止まる）。テストを直したいときは `/clear` してから、もう一度 `/write-tests` を使う。

## 守ること

- 実装のコード（テスト以外のファイル）は書かない。テストを動かすのに空の関数が要る言語でも、中身は書かない（「未実装」のエラーを返すだけ）。
